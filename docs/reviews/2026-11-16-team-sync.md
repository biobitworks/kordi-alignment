## Finding R1: advertised plugin schema does not match tested validation contract

**Priority:** medium; cross-component follow-up in [plugin issue #3](https://github.com/biobitworks/kordi-alignment/issues/3). Do not interpret passing tool tests as complete plugin-schema parity.

At PR #1 head, `extensions/alignment-compass.cjs` advertises `id` as an unrestricted string, and evidence elements as unrestricted strings. `redteam/fixtures/assess.schema.json` instead declares ID syntax, evidence nonblankness, and a 500-code-point maximum. The Python suite validates that fixture, not the schema sent to providers.

Reproduced inputs, each inside an otherwise valid `scope: "fictional"`, `items: [...]` request:

1. `{ "id": "bad id" }`
2. `{ "id": "valid", "lawChaos": 0, "goodEvil": 0, "evidence": [" "] }`
3. The same scored item with a single evidence string containing 501 ASCII characters.

For each: advertised schema accepts; fixture schema rejects; runtime scorer rejects. This is an interface/test-coverage mismatch, not evidence that invalid inputs bypass the scorer or grant privileges. The core remains fail-closed for these cases.

**Requested gate:** validate shared boundary fixtures against the actual captured registration schema and runtime, align representable constraints, retain omitted-input UNKNOWN, and document duplicate-ID checking as a separate runtime constraint. Keep corrective plugin work in its lane rather than silently expanding the tool PR.
